# توکن‌ها

توکن یعنی یک تصمیم طراحی با نام. هیچ مقدار خامی (رنگ، فاصله، گوشه، مدت) در کد اجزا و صفحه‌ها نیست.

## سه سطح

```
primitive  ──►  semantic (+ یک فایل برای هر تم)  ──►  component
پله‌های خام       نقش‌ها: «متن ثانویه»، «سطح برگ»        «زمینهٔ دکمهٔ اصلی»
```

| سطح | فایل | قاعده |
| --- | --- | --- |
| پله (primitive) | `src/ui/tokens/primitive.json` | فقط مقدار خام: پلکان‌های رنگ OKLCH، عددها. هیچ معنایی ندارد. |
| نقش (semantic) | `semantic.json` (مستقل از تم: فاصله، گوشه، اندازه، حرکت، لایه) + `semantic.light.json` و `semantic.dark.json` (رنگ و سایه) | فقط به پله ارجاع می‌دهد. **همهٔ تم‌ها دقیقاً یک فهرست کلید دارند.** |
| جزء (component) | `component.json` | فقط به نقش ارجاع می‌دهد، هرگز به پله. فقط وقتی جزئی به تصمیمی نیاز دارد که نقش عمومی ندارد. |

`bun run tokens` از این‌ها `src/ui/tokens/build/` (CSS و تم Tailwind) را می‌سازد. `tokens.test.ts` این‌ها را اجبار می‌کند: هم‌خوانی خروجی با منبع، کامل‌بودن هر تم، نبود ارجاع جزء به پله، و کف‌های کنتراست [color.md](./color.md) در هر تم.

> **خروجی build باید پس از کلون تازه وجود داشته باشد.** اکنون `build/` در `.gitignore` است و `bun run dev` بدون اجرای دستی `bun run tokens` با صفحهٔ بی‌سبک بالا می‌آید. راه‌حل در [implementation-plan.md](./implementation-plan.md)، گام ۰.

## نام‌گذاری

- شکل: `دسته-نقش[-شدت][-حالت]`. مثال: `text-subtle`، `bg-brand-hover`، `border-focus`.
- نام می‌گوید **برای چه**، نه **چه رنگی**: `text-danger`، نه `text-red`.
- دسته‌های رنگ: `surface-*` (سطحی که چیزها رویش می‌نشینند)، `bg-*` (پرکنندهٔ یک عنصر)، `text-*`، `icon-*`، `border-*`، `nuqta-*`.
- مقیاس‌ها با اندازهٔ پیراهنی (`sm`، `md`، `lg`) یا عدد پله (`space-4`).

### هم‌ارزی با نام‌های PR #51

نام‌های این سند و نسخهٔ قابل‌مرور کوتاه‌شده‌اند. کلیدهای موجود در کد **تغییر نام نمی‌دهند** مگر در این جدول آمده باشد؛ فقط مقدارشان عوض می‌شود.

| این سند | کلید در کد | کار |
| --- | --- | --- |

| `surface-inverse`، `text-on-inverse` | `bg.neutral-bold`، `text.on-neutral` | همان کلید |
| `nuqta-*` | `knowledge.*` (سطح و خط و گوشه برای هر وضعیت) | **جایگزین شود:** پنج رنگ `nuqta.*`؛ کلیدهای `knowledge.*-surface/-border/-radius/-rule/-shadow` حذف |
| | `mabda.type-*-bg/-fg/-border/-icon` | **حذف** (نوع دیگر رنگ ندارد)، جز یک `mabda.type-constraint-icon` |
| | `shadow.brand-glow` | **حذف** |
| `shadow-1/2/3` | `shadow.seated/raised/overlay` | همان کلید، مقدار تازه؛ `shadow.overflow` حذف |
| `blur-bar`، `saturate-bar` | ندارد | **اضافه شود** (`effect.bar-blur`، `effect.bar-saturate`) |
| `sidebar-*`، `content-*`، `measure`، `margin-col`، `inspector`، `bar-*`، `dialog-*` | بخشی در `overlay-width.*` و `container.*` | **اضافه یا هم‌مقدار شود** با جدول پایین |
| `duration-instant/fast/base/moderate/slow/stagger` | `duration.instant/fast/normal/slow/slower/stagger` | همان کلید، مقدار تازه: ۸۰ · ۱۴۰ · ۲۰۰ · ۲۸۰ · ۳۶۰ · ۳۰ |

| `ease-standard`، `ease-enter`، `ease-exit`، `ease-settle` | `ease.move`، `ease.enter`، `ease.exit`، ندارد | مقدار تازه طبق جدول «منحنی»؛ `ease.settle` اضافه شود |
| `z-*` | `layer.*` | همان کلیدها و همان ترتیب؛ مقدارهای کد می‌مانند (`z-raised` = `layer.raised`، `z-bar` = `layer.sticky`، `z-skip` = `layer.skip-link`) |
| `dialog-sm/md/lg/xl` | `overlay-width.sm/md/lg` | `sm` ۴۰۰ می‌ماند، `md` ۴۸۰ ← ۵۲۰، `lg` ۶۴۰ ← ۷۲۰، `xl` ۹۶۰ اضافه شود؛ `overlay-width.xs` (۲۴۰) فقط کمترین پهنای منو |
| سبک‌های تایپ | `type.*` | مقدار تازه مطابق [typography.md](./typography.md)؛ واحد `rem` |

## افزودن یا تغییر توکن

1. اول بگرد: آیا نقشی با همین معنا هست؟
2. توکن تازه با **معنا** تعریف می‌شود و در همهٔ تم‌ها مقدار می‌گیرد.
3. `bun run tokens`، `bun run test` (کنتراست)، `bun run screens` (هر دو تم).
4. در این سند و [color.md](./color.md) ثبت شود. توکنِ بی‌سند پذیرفته نمی‌شود.
5. حذف توکن: اول همهٔ کاربردها برداشته شود؛ نام قدیمی نگه داشته نمی‌شود.
